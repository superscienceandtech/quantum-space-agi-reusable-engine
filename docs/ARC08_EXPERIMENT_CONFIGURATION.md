# ARC-08 Experiment Configuration and Manifest Foundation

**Status:** Engineering schema only. It contains no approved scientific task,
cohort, eligibility policy, split policy, acceptance threshold, or acquisition
authorization.

## Purpose and boundaries

`quantum_space_agi.ml.experiment_manifest` provides immutable declarations for a
future experiment and a deterministic manifest linking the declaration to
portable artifact references. It performs no network access, filesystem reads
or writes, data acquisition, split generation, model fitting, prediction, or
evaluation. Missing decisions remain explicit through `None` values and review
statuses rather than being filled with scientific defaults.

The package reuses the project's lowercase 64-character SHA-256 convention.
Snapshot bytes and persisted evidence reports remain governed by their existing
artifact and persistence APIs; this schema stores portable references and
checksums but does not replace those APIs.

## Configuration schema

Version 1 is identified by
`arc08-experiment-configuration/1`. The frozen `ExperimentConfiguration`
contains:

- Experiment ID, description, type, lifecycle label, and optional timezone-aware
  creation timestamp.
- A `ResearchTask`: objective, target field/unit, feature fields/units,
  intended inference, and a decision declaration.
- A `DatasetDeclaration`: source identity/table, query artifact, raw snapshot
  artifact, schema artifact, extraction-metadata artifact, and dataset version.
- One `PolicyDeclaration` for each versioned policy ID: cohort,
  inclusion/exclusion, missing values, non-positive values, limit codes,
  uncertainty, controversy/solution status, identity/duplicates, split,
  evaluation/acceptance, scientific claims, and data access/retention.
- Identity, grouping, split, model/evaluation, and execution-environment
  declarations, including optional seeds and output/evidence artifact links.

Unknown or not-yet-selected values are represented by `None`; no V1 field
silently substitutes a recommended value. Each policy and task/split/model
decision has an explicit status: `PROPOSED`, `PENDING_REVIEW`, `APPROVED`, or
`NOT_APPLICABLE`. An `APPROVED` declaration requires an authority string and at
least one structurally valid evidence reference. This validates only the
caller-declared record. The code does not authenticate the authority or read
the referenced approval. `NOT_APPLICABLE` requires a rationale.
The split-policy and evaluation-policy statuses must agree with their
corresponding detailed split and model/evaluation sections.

Artifact references use portable relative POSIX paths and optional lowercase
SHA-256 values. Absolute paths, traversal segments, backslashes, and drive-like
paths are rejected. Environment fields are declarative metadata; paths belong
in `ArtifactReference` values. Execution commands are token tuples and reject
absolute path arguments. No checkout-specific path is generated by the API.

Free-text metadata uses a narrow, token-boundary check for obvious POSIX paths
with directory components, Windows drive paths, and UNC paths. Ordinary
scientific notation such as `mass/radius`, URLs such as `https://...`, package
identifiers, and ordinary single-backslash notation remain valid. This is a
portability safeguard for declarations, not a general-purpose path parser. A
filesystem location must be represented as an `ArtifactReference`, whose
relative-path rules are stricter than free-text validation.

## Canonical serialization and hashing

`serialize_experiment_configuration()` returns compact UTF-8 JSON with sorted
object keys, preserved non-ASCII text, no BOM, and no non-finite JSON numbers.
The serialized byte sequence is canonical for the V1 schema. The configuration
SHA-256 is calculated over those exact bytes by
`experiment_configuration_sha256()`; any serialized field change changes the
digest. Any change to field meaning or canonicalization requires a new schema
version rather than silently changing V1 semantics.

Creation timestamps are optional caller inputs, so deterministic configurations
must omit them or reuse the same explicit timestamp. No clock value is inserted
automatically.

## Manifest schema and linkage

`create_experiment_manifest(configuration, configuration_path)` produces
`arc08-experiment-manifest/1`. It calculates the configuration digest and links
the portable configuration reference, source snapshot reference (when
declared), execution environment, and output/evidence references. The manifest
does not query those paths or recompute the source snapshot checksum.

When both `lockfile_reference.sha256` and `lockfile_sha256` are supplied, they
must match exactly. A lockfile reference may be declared before its checksum is
known; a standalone `lockfile_sha256` still requires a lockfile reference.

`validate_experiment_manifest(manifest, configuration)` verifies the
configuration digest, experiment ID, snapshot reference, environment, and
outputs against the supplied configuration. `serialize_experiment_manifest()`
performs that check before returning deterministic compact UTF-8 JSON. Snapshot
and output checksums are optional until their artifacts exist; the schema does
not invent them. This validation checks declarations and linkage only; it does
not check artifact existence, read artifact contents, or independently verify
artifact checksums. Use the existing artifact verification APIs for those
operations.

## Interpretation limits

- A reproducible configuration does not prove that its scientific policy is
  valid or approved.
- A manifest checksum does not prove source authenticity or snapshot
  consistency.
- A declared approval record does not prove that the approval or approver is
  authentic.
- A successful manifest validation does not establish scientific acceptance,
  NASA authorization, data-use permission, or model performance.
- This implementation does not change the acquisition readiness result, which
  remains `NOT_READY`, or the pending scientific review status.

No NASA data, network response, model, prediction, metric, or scientific result
is produced by this foundation.
