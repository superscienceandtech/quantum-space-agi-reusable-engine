# ARC-08 Exploratory Baseline ML Policy Decision Matrix

**Status:** Research recommendations for review only. This document does not approve the scientific task, eligibility rules, dataset extraction, model evaluation, or training.

**Evidence accessed:** 2026-11-09. NASA documentation is cited inline and listed in Sources. Repository state and prior live-query observations are distinguished from current NASA documentation. No new NASA TAP data query was made for this review.

## Scope and repository state

This matrix concerns the proposed exploratory task in [`ARC08_BASELINE_ML_TASK_SPEC.md`](ARC08_BASELINE_ML_TASK_SPEC.md): estimate archive-reported `pl_bmasse` from `pl_rade`, with candidate cohort `default_flag = 1 AND pl_bmassprov = 'Mass'`. It does not establish that archive-reported mass is independent physical truth, that the feature is available for a real decision, or that the task is scientifically useful.

The current candidate count of 2,211 is a prior live aggregate observation recorded in the handoff/task specification. It is the count for the candidate predicate, not a count of records eligible after validity, identity, duplicate, or grouping review. The handoff records 1,586 with non-null radius from an earlier bounded audit; neither number describes a retained snapshot. The archive can change between queries.

ARC-03's current `Dataset` copies top-level record and metadata mappings but is shallow for nested values ([`data/models.py`](../src/quantum_space_agi/data/models.py)); `DataSchema` validates declared structure/types, not scientific eligibility ([`data/schemas.py`](../src/quantum_space_agi/data/schemas.py)). The current NASA adapter is bounded to at most 100 rows, has no filter or pagination argument, hashes but does not retain response bytes ([`data/adapters/exoplanet_archive.py`](../src/quantum_space_agi/data/adapters/exoplanet_archive.py)). The proposed full extraction therefore requires separately reviewed acquisition and durable snapshot work.

## Provisional working recommendations

These are review proposals, not approvals:

1. Keep the target `pl_bmasse`, exact `pl_bmassprov='Mass'`, and the sole candidate feature `pl_rade`; do not add mass-derived, radius-derived, uncertainty, identifier, density, or post-target fields as predictors.
2. Preserve source values and nulls verbatim. Report missing, absent, malformed, non-finite, zero, and negative values distinctly. Do not coerce null to zero, impute radius, or apply undocumented limit-code meanings.
3. Treat missing target/feature and non-finite values as mechanically ineligible for ordinary regression; quarantine zero/negative and limit-flag cases until row semantics and final cohort rules are approved.
4. Keep uncertainty fields as raw audit metadata only; do not require them, use them as features, or weight the baseline. Revisit sensitivity analysis only with an approved statistical interpretation.
5. Preserve controversy/solution fields and report distributions. Do not filter by them until the scientific population is approved.
6. Audit duplicate planet identities and exact host/reference strings; never deduplicate by query order. Quarantine missing or ambiguous grouping identities for grouped evaluation.
7. Require host-disjoint partitions, audit reference overlap, and stop if the approved grouping makes a viable test partition impossible. No random-row fallback.
8. Retain the exact raw extraction artifact and a versioned manifest before deriving any model-ready rows.

## Approval gates before extraction

Dataset extraction remains blocked until the team/reviewer approves:

- the scientific purpose, prediction timing, and interpretation of archive-reported target values;
- the target and feature validity rules, including zero/negative cases and active `ps` limit-code semantics;
- treatment of uncertainty, controversy, solution status, duplicate names, and missing/ambiguous identity;
- host versus host-reference grouping, split proportions, minimum feasible group counts, seed, and final-test handling;
- durable snapshot storage, retention/access/distribution terms, provenance, citations, and schema/policy versioning;
- baseline/metric interpretation and any acceptance threshold before test results are viewed.

The exact 2,211 candidate count is planning evidence only. It does not remove these blockers or authorize extraction. The separate task specification remains exploratory and the ML readiness decision remains NO-GO.
